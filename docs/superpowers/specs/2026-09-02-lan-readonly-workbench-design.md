# wxFomo 局域网只读工作台设计

## 目标

在 Mac 上继续监听企业微信群并运行所有数据处理，向同一局域网内的 Windows 电脑提供一个只读网页工作台。网页以现有 SwiftUI App 和 `docs/screenshots/` 的真实截图为视觉与信息架构基准，复刻 wxFomo 的导航、页面、状态和数据呈现，而不是制作一个简化消息列表。

Windows 只需要浏览器，不安装监听器，也不直接访问企业微信或 SQLite 文件。

## 已确认约束

- 监听端是当前 macOS 13 / Swift 5.2.4 机器。
- Windows 与 Mac 位于同一局域网。
- 企业微信监听只发生在 Mac。
- Windows 工作台严格只读。
- 现有完整 SwiftUI App 要求 macOS 14 / Swift 5.10，不能作为当前 Mac 上的网页后端。
- 当前 Mac 尚不存在 `messages.sqlite3` 和 `workspace.sqlite3`；第一批真实数据来自独立企业微信群监听器。
- 不把 API Key、访问令牌、私钥、完整本机路径或配置文件内容发送给浏览器。

## 范围

### 工作台页面

网页保留现有左侧导航分组和页面结构：

- 消息：收件箱、重点捕捉、提醒中心、各监听群。
- 工作台：Meme 观察、市场趋势、分析记录、监控规则、交易工作台、自动化交易。
- 设置：声音与提醒、配置中心、运行诊断。
- 采集状态：企业微信状态、通知读取状态、监听状态、最近消息时间。

页面使用与现有 App 一致的深色三栏布局、286px 左侧栏、计数徽标、状态色、筛选工具栏、卡片密度和中文文案。Web 中没有 SF Symbols，因此使用本地 SVG 图标实现等价视觉，不加载第三方 CDN。

### 只读规则

Windows 可以：

- 查看、筛选、搜索和分页。
- 切换群聊、时间范围和工作台页面。
- 查看已生成的分析、提醒、行情、规则、交易与诊断记录。
- 复制消息、地址和公开链接。

Windows 不可以：

- 启动或停止监听。
- 添加或删除监听群。
- 创建、修改、确认或删除任何记录。
- 发起 AI 分析、行情交易、买入、卖出、自动化试跑或规则执行。
- 查看或修改 API Key、语音 Key、交易签名材料及其它凭据。

原 App 中的写操作不伪装成可用按钮：危险操作隐藏；为了保持页面结构而保留的控制显示为禁用状态，并明确标注“仅可在 Mac 操作”。

## 架构

```text
企业微信通知
    ↓
macOS 13 独立监听器
    ↓ 单一写入者
私有消息 SQLite
    ↓ 只读查询
Mac 局域网 HTTP 服务 ─────→ Windows 浏览器工作台
    ↑ 只读查询
现有 wxFomo 工作区数据库（存在时）
```

### 1. 消息持久化

扩展 `scripts/wecom-group-listener.swift`，在终端输出之外把每条已验证的群消息保存到私有 SQLite。默认路径为：

```text
~/Library/Application Support/wxFomo LAN/messages.sqlite3
```

数据库目录权限为 `0700`，文件权限为 `0600`。表至少保存：稳定事件 ID、Notification Center 记录号、群名、发送者、正文、消息类型、投递时间和首次入库时间。稳定事件 ID 建立唯一约束，监听器重启或通知记录更新不能产生重复消息。

监听器仍是唯一写入者。网页服务只用 SQLite 只读 URI 打开数据库，不执行 schema 迁移或写事务。

### 2. Mac 局域网服务

新增一个兼容系统 Python 3.7 的无第三方依赖服务。它负责：

- 提供本地 HTML、CSS、JavaScript 和 SVG 资源。
- 提供同源、只读 JSON API。
- 读取私有消息 SQLite。
- 当原生 wxFomo 的 `messages.sqlite3` 或 `workspace.sqlite3` 将来存在时，以只读适配器输出分析、提醒、行情、规则和交易记录。
- 对不存在的数据源返回 `available: false` 和明确原因，页面显示真实空状态，不制造演示数据。

服务默认监听端口 `8765`。启动时解析 Mac 的局域网 IPv4，并打印 Windows 可打开的地址。必须显式使用 `--allow-lan` 才能监听非回环地址，避免误操作暴露数据。

### 3. 浏览器工作台

网页采用无构建步骤的 HTML、CSS 和 ES2018 JavaScript，兼容当前 Windows 10/11 的 Edge、Chrome。代码按页面拆分为消息、提醒、分析、Meme/市场、规则/自动化、交易、设置/诊断模块，共用导航、数据请求、格式化与空状态组件。

页面首次加载获取工作台摘要；消息页以稳定 `(observed_at, event_id)` 游标分页。可见页面每 2 秒进行一次带游标的增量请求，使新消息在 Windows 上近实时出现，同时避免重复下载完整历史。页面不可见时暂停轮询。

## 只读 API

首版 API 只接受 `GET` 和 `HEAD`：

- `/api/bootstrap`：应用状态、群列表、侧栏计数和数据源可用性。
- `/api/messages`：时间范围、群名、关键词、类型和游标筛选。
- `/api/alerts`：提醒列表和来源消息。
- `/api/analyses`：分析任务、结果和来源引用。
- `/api/meme`、`/api/market`：观察池、行情快照和群聊热度。
- `/api/rules`、`/api/automations`：规则与运行记录。
- `/api/trades`：交易记录和状态，不返回签名材料。
- `/api/settings/status`：服务是否已配置，只返回布尔状态。
- `/api/diagnostics`：监听、数据库和数据源健康状态。

所有 `POST`、`PUT`、`PATCH`、`DELETE` 返回 `405 Method Not Allowed`。API 数据模型是面向页面的只读 DTO，不把数据库行或内部配置对象原样透传。

## 安全边界

- 认证凭据保存在 `0600` 私有文件中；部署者可将其设置为固定访问密码，未预设时首次启动仍生成至少 32 字节随机值。
- Windows 打开登录页后输入访问密码；浏览器只保存在 `sessionStorage`，关闭窗口即清除。
- API 要求 `Authorization: Bearer`，用常量时间比较验证。
- 不启用 CORS；设置严格 CSP、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer` 和 `Cache-Control: no-store`。
- 日志不记录令牌、消息正文、群名或查询词。
- 服务只在显式 `--allow-lan` 时监听局域网；文档明确局域网 HTTP 不能防止同网段窃听。支持可选 `--tls-cert` 与 `--tls-key`，需要更强保护时启用 HTTPS。
- 浏览器绝不获得 API Key、交易签名材料或完整配置文件。

## 空状态与降级

消息页在独立监听器写入第一条消息后即可真实工作。其它工作台页面只有在相应 Mac 数据源存在时展示数据；当前 Mac 没有原生工作区数据库时，页面保留与原 App 一致的结构，并显示“当前 Mac 后台尚未生成此类数据”。

数据库临时锁定时返回可重试状态，浏览器保留已有内容并退避重试。schema 不兼容、数据库损坏或权限错误显示在运行诊断页，不循环刷屏，也不回退到伪造数据。

## 测试与验收

### 自动测试

- 监听器：消息入库、重复事件幂等、低记录号新消息、数据库权限和写入错误。
- 服务：令牌验证、只读方法限制、筛选分页、秘密字段脱敏、缺失数据源空状态、SQLite 锁定与 schema 错误。
- API：每个端点使用临时数据库验证 DTO，不依赖真实群消息。
- 前端：路由、侧栏计数、筛选、分页、空状态和增量合并使用固定 JSON fixture 验证。

### 实机验收

- Mac 监听真实目标群，新消息写入后 Windows 页面在 3 秒内出现且不重复。
- Windows 页面与 `docs/screenshots/message-filter-tabs-real.jpg`、`analysis-workbench.png`、`alerts-token-links.png`、`configuration-center-real.jpg` 的布局和视觉层级一致。
- 所有导航页面可打开；缺少数据的页面显示真实空状态。
- Windows 无法通过 UI 或 HTTP 方法修改 Mac 数据。
- 关闭网页不会影响监听；停止网页服务不会影响消息入库。

## 交付顺序

1. 给监听器增加幂等 SQLite 持久化，确保从现在开始积累真实消息。
2. 建立带认证的只读服务和消息 API。
3. 复刻全局外壳、侧栏、收件箱、群消息与运行诊断。
4. 复刻其它工作台页面并连接可用的原生数据库；缺失数据源使用明确空状态。
5. 在 Windows 浏览器完成视觉、实时性和只读安全验收。

## 非目标

- Windows 本机监听企业微信。
- 公网或云端同步。
- Windows 端写配置、执行分析或发起交易。
- 修改现有 SwiftUI 工作台的交互设计。
- 为缺失的 Mac 后台数据生成示例或模拟结果。
