## 当前阻塞不是 Mac IP 或 VPN

已核对 Signal 的 `src/app/api`、`src/app`、`src/lib`、`scripts` 和既有授权代码：当前还没有 WeCom 接收器、相关存储、读 API 或 `/wecom` 页面。`src/lib/admin-auth.ts` 是无 userId 的单管理员会话；`src/proxy.ts` 尚无精确机器写入口例外。

因此，Mac 代码推送成功不等于网站已经能收数据。不能通过关闭网页认证、开放原始聊天、复用 AI Key 或在公网暴露 Mac 工作台来绕过缺失的接收器。

## 网站端按现有 v2 规范实施

1. **修正合成基准。** 市场报告的两条来源昵称不同，`uniqueStatementCount/duplicateCount` 应为 `2/0`；Mac 提供 [候选载荷和重签向量](../../scripts/fixtures/signalhub-sync/README.md)。保留原固定样例作为历史证据，不偷偷修改其清单哈希。Signal 接受修正后回传提交号。
2. **独立接收与存储。** 沿用已约定的回环地址接收器、独立 SQLite 和 `POST /api/wecom/ingest`。验证实际请求字节的 HMAC、时间、设备、正文上限及严格 v2 结构；nonce 与对象写入同事务，持久提交后才能确认。实现同版同字节 duplicate、低版本 stale、同版异内容冲突和重启后防重放。
3. **授权读取。** 实现报告列表/详情、CA 历史/active、设备状态 API；全部服务端校验本人会话及设备权限，响应 `private, no-store`。仅精确 POST 写入口豁免网页登录跳转且仍强制 HMAC，不豁免其他方法、子路径或任何读接口。
4. **独立 `/wecom` 页面。** 展示完整 briefing、范围缺口、来源元数据、实时跨群 CA 和分开的监听/AI/CA 状态。原文不在网站，不能造“查看原文”。不接交易、热门币榜或其他市场功能。
5. **可见时刷新与提醒去重。** CA 每 15 秒、报告每 60 秒；隐藏暂停、重开即读。首次进入不弹旧消息；catchup、延迟、过期均不冒充新提醒。保持 firstReceivedAt、revision、notificationVersion 和关闭后不复活语义，退出登录清空本会话缓存。
6. **补测试并回传。** 使用临时数据库、公开合成密钥和合成消息，先验证下表，再提供网站实现分支/提交、命令及结果。不要以文档样例 PASS 代替接收器或浏览器实测。

本人授权是上线门槛：首版若继续单管理员模式，必须确认管理员权限为本人独占；如果权限已共享，先实现真实用户身份和设备归属。不能默认“任何已登录的人”都能看到群资料，也不要求 Mac 新增客户端自报 owner 字段。

## 双端合成验收清单

| 链路 | 必须证明 |
| --- | --- |
| 完整报告 | Mac 合成源→导出→签名→网站持久化→授权详情，完整 briefing/范围/引用闭包保持一致，`sources=[]` |
| 实时 CA | 两个合成群达到既定阈值→入队→接收→可见页面；独立记录各段时间后再判断是否达到约 60 秒目标 |
| 可靠性 | 确认丢失重传不重复、乱序不倒退、重启保留 nonce/首次接收时间；断网期间已确认的报告仍可授权查阅 |
| 提醒 | 过期和提前关闭、冷却、catchup、首次进入、页面重开、修订去重均符合协议 |
| 权限 | 匿名读 401、无权设备读 403、不存在资源不泄露；机器写豁免不影响读权限；退出登录清缓存 |
| 边界 | 错签名、重放、v1、未知字段、原文、超限、非法引用/计数拒绝；限流与资源不足时保留 Mac 未确认队列 |

Mac 可配合提供临时合成库和固定载荷，继续使用独立同步器；不得在联调中读取真实群消息或调用付费 AI。现有生产地址白名单不为测试而放宽，测试使用注入传输或双方约定的隔离测试环境。
