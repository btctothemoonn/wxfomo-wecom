# wxFomo · 企业微信群消息总结

这是 wxFomo 的精简分支：**Mac 监听，浏览器查阅**。只做群消息收集、规则筛选和总结，不做交易或行情平台。

## 保留的功能

- 按群名白名单读取 macOS 企业微信通知，保存在本机 SQLite，支持查阅和搜索。
- 新消息中提取“昵称：正文”的实际发言昵称，保留机器人名称和原文；旧消息不改写。
- 本地关键词规则、重点捕捉、告警。
- MiniMax 大陆站 2 小时、6 小时、24 小时定时总结，保留来源引用和失败状态。
- 每份报告内展示 CA 讨论：涉及群、提及数、去重发言、重复传播及最多 5 条原文示例。
- 只读网页、密码认证、AI 配置状态和监听诊断。

移除：原生 SwiftUI App、交易/钱包/自动交易、市场趋势/热门币榜/价格关注池、语音和旧工作区兼容读取。独立 Swift 通知监听器仍保留，不需要构建旧 App。

## 启动和查阅

在本仓库目录运行：

```sh
zsh scripts/start-wxfomo-lan.sh
```

本机打开 http://127.0.0.1:8765/ ，输入已有访问密码。监听终端必须保持运行；退出用 Ctrl+C。若已运行，不要再开第二套监听进程。

需要局域网访问时：

```sh
zsh scripts/start-wxfomo-lan.sh --allow-lan
```

打开终端显示的具体地址（局域网模式不保证监听 127.0.0.1）。不要暴露到公网；默认 HTTP 没有传输加密。VPN、跨路由或访客网络可能导致其他电脑无法访问。

运行环境：macOS、系统 Python 3.7+、Swift 5.2+（Command Line Tools）。没有 npm 或 pip 依赖。按系统提示给启动监听器的终端必要的通知数据库读取权限。

## 群配置与数据

群白名单：`~/.config/wxfomo/wecom-groups.txt`，每行一个完整群名。修改后重新启动监听器。

数据目录：`~/Library/Application Support/wxFomo LAN/`

| 文件 | 用途 |
| --- | --- |
| messages.sqlite3 | 监听消息与游标 |
| messages.sqlite3.relay.json | 新消息归因的固定生效边界，勿删除或重建 |
| analysis.sqlite3 | 规则、周期任务和历史 AI 结果 |
| access-token | 网页访问密码（保留旧文件名） |
| ai-credentials.json | 本机 MiniMax 凭据，不上传 Git |

启动会沿用已有文件。更换代码不需要清空数据库，也不要把密钥放进网页目录。MiniMax 凭据仅由后台读取，网页不显示或修改密钥。

## 总结与 CA 统计口径

- 三种周期读取本机已捕获消息，覆盖全部已配置群。程序停机不是补齐群历史的工具。
- 网页可按日期查阅最近三个北京时间自然日的报告，按周期结束日期归类；更早报告仍留在数据库，没有删除或重新分析。
- 后续 AI 报告使用六栏模板：本期范围、10秒速读、重点标的与大盘、消息面与风险、CA索引、来源与缺口。普通业务群改为关键进展、重要通知、风险阻塞、待办清单。旧报告保留原文，不补跑。
- 总结仅基于捕获的通知文本，不是完整群聊；程序展示实际分析条数与缺口，M 开头为本报告的本地引用编号，展开可见发言人、群名、采集时间及原文。图片、语音、附件、链接正文未读取，未进行外部核验。
- 保留自述／转述／推测和分歧更正，数据区分历史快照与预测，CA 原样复制并校验直接来源，不推断公链归属。市场内容仅来自群聊，不接行情或交易。定时仍为 2／6／24 小时；分析调用未指定时间时默认最近 12 小时（不新增手动生成接口）。
- 总结页每 30 秒检查新报告；状态刷新不会收起已展开的来源，新报告更新时也保留来源展开状态。
- 简报模板按 2h / 6h / 24h 切换，一次阅读一份报告；支持日期与报告时间选择，后台刷新保留当前选择。新模板为顶部速读、项目主体、风险与 CA 侧栏；窄屏单列。来源默认折叠，使用本地短编号，不展示内部消息 ID。
- CA 统计按报告冻结的完整消息集合计算，不按当前消息列表页数计数。旧报告最多展示 50 个 CA；新模板索引收录本期重点标的，每个标的最多一个 CA，不同链或 CA 分条，每项最多 5 条来源示例。
- 同昵称、同正文视为重复传播的估算；昵称不等于真实身份，也不代表独立认可人数。
- 明确不同链的相同 EVM 地址分开统计；未说明链的地址暂按群分开，避免错误合并。
- 地址格式或群内标注不是链上验证。没有引用匹配的旧 AI 摘要时，显示原文而不编造摘要；不会因此补调 AI。
- CA 摘要允许引用同群、前后两条且相隔不足 5 分钟的上下文；引用涉及多个 CA 或链、无法唯一归属时，会提示核对原文，不强行关联。
- 来源缺失会标记统计不完整。报告失败会保留失败状态，不显示成成功。
- 新完成报告的用量累计本次成功分析中的分块、汇总和格式修复请求；提供方漏报的用量显示未知。此前失败尝试的消耗不包含在内，旧报告不回写。

通知可能受免打扰、预览隐藏、专注模式、前台抑制和系统清理影响；采集不到的消息无法总结。图片、视频可能只有通知占位文字，不能据此还原全部聊天记录。
